## 一、引擎升级 v0.1.32 → v0.1.44.1：单路 +32%

### 背景

上游 Strata 在我们部署之后又发了 12 个版本（v0.1.33 → v0.1.44.1）。逐版核对 release notes，
对这台机器（单卡 5090 Laptop、IQ3_XXS、专家 38% 驻显存）有意义的变化集中在 v0.1.41-v0.1.44。

### 实测

同一iq3_xxs配置、同一组 3 个中文问题、~800 token 输出、读引擎自报计时：

| 引擎 | 3 轮 tok/s | 中位 |
|---|---|---:|
| v0.1.32（升级前） | 79.4 / 83.3 / 93.6 | 83.3 |
| **v0.1.44.1** | **112.5 / 100.2 / 110.3** | **110.3** |

**+32%**，远超预期（预估 +5~15%）。三个新默认在这台机器上叠加生效：

1. **Route tail skip**（`STRATA_ROUTE_TAIL_SKIP=7` 默认开）：解码时跳过低排名 miss 专家
2. **PCIe 实测校准**：启动时实测链路吞吐（49 GB/s）动态分配 GPU/CPU 专家比例（0.55）
3. **短 prompt CPU 分担**：<1024 token 的 prompt 由空闲 CPU 分担部分专家

### 升级坑（重要）

**连续重启会失败**：旧引擎退出时 33GB 锁页内存释放很慢，下一个实例立刻启动会差
0.3-0.5GB（arena 需要 39.97 GiB）直接失败，引擎日志自带提示
`wait for an engine that is still exiting`。**重启间隔必须 ≥70 秒**，或先确认可用物理内存。

### 顺带修正

- 副标题被英文模型名覆盖的旧代码（health 回调）已删
- v0.1.44.1 附带 Windows commit 限额守卫（92.5GB 页文件+内存模型，防静默 0xC0000409）

## 二、并发与 KV 池：找到天花板和墙

### batch 扫描（--batch N，每槽 256K）

| 配置 | 单路 | 满载聚合 | 结论 |
|---|---:|---:|---|
| batch2 × 256K | 73-81 | **82.6** | 甜点：双路长文档互不挤压 |
| batch3 × 256K | ~71 | **81.9**（每路 85-93） | **当前默认** |
| batch4 × 256K | — | 58.9 | 明显衰减 |
| batch8 × 256K | — | 未测 | 不推荐 |

**核心发现：总吞吐天花板 ≈ 76-82 tok/s，由内存带宽决定**——并发是"分流"不是"提速"。
多人同时用会各自变慢，但不会崩。

### KV 池极限（满仓填充实测）

往每一路灌到接近 256K，测同时在线 token 总量的墙：

| 同时在线 | KV 总量 | 结果 | RAM 余量 |
|---:|---:|---|---:|
| 2 × 245K | ~6.4 GB | ✅ 零错误 | ~5.5 GB |
| 3 × 245K | ~9.1 GB | ✅ 零错误 | ~3 GB |
| **4 × 245K** | **~13 GB** | ✅ 零错误 | **0.4 GB ⚠️ 墙** |

**911,520 token 同时在线**（4 路各 94% 满）通过——但 0.4GB 余量是禁区。
KV 是流式分布（大头显存、溢出进内存），实际池容量比"全在内存"的估算大得多。

### 最终运行配置

`--batch 3 --max-context 262144 --kv-resident 65536`（KV 从内存挪 0.9GB 进显存，
换启动余量；专家缓存自动缩到 6633 slots / 10.73GB）。

## 三、MTP 参数复扫：现配置确认峰值

6 个变体（spec 2/6、min-p 0.3/0.5/0.9 等）全部输给现配置 **spec 4 / min-p 0.7**：

| 变体 | 结果 |
|---|---|
| spec 2 | 接受率 86% 但窗口太短，浪费 |
| spec 6 | 错误猜测变多，-26% |
| min-p 0.5 / 0.3 | 阈值放太松，-28% / -36% |
| + --batch-mtp | 单卡上是负优化，-30% |

结论：**spec 4 与 70% 接受率正好匹配**，出厂推荐就是峰值，固化。

## 四、网页技能包：巧巧长出七样本事

架构：server.py 加同源端点（全部 401 门禁 + SSRF 防护），浏览器端意图识别后
并行调用，资料注入上下文，key 全程不出服务器。

| 端点 | 功能 | 实测 |
|---|---|---|
| `/search?q=` | Bing RSS 搜索（免 key，查询清洗：剥口语词） | ✅ 6 条 |
| `/weather?q=` | Open-Meteo 气象（免 key）：当前温湿风 + **日落时间 + 日落前后中高云量 + 降水概率 + 晚霞判定** | ✅ 上海：27.5°C、日落 17:20、判定"高" |
| `/calc?expr=` | ast 白名单安全计算（四则/幂/取模/sqrt/log/三角，支持 ×÷^ 全角） | ✅ `2**10+sqrt(144)`=1036 |
| `/news?topic=` | 新闻头条（**国内修正**：news.bing.com 在国内为空，改走 cn.bing.com/search+新闻 后缀） | ✅ 6 条 |
| `/rate?text=` | 实时汇率（open.er-api.com 免 key；币种按文本出现位置解析） | ✅ 500日元→21.19 CNY |
| `/read?url=` | 网页阅读器：抓单页抽正文（12K 截断；**SSRF 防护**：内网地址拒绝） | ✅ specul.com 3798 字 |
| `/quote?codes=` | 腾讯行情（免 key，GBK；A股/港股/指数，支持 sh/sz/bj 前缀与指数名） | ✅ 贵州茅台 1329.00 +1.22% |

**晚霞问题的正确解法**：这类问题用网页搜索答不准（Bing 返回的是新闻页不是气象数据）。
专门的气象通道拿到日落时间与云量后，巧巧的回答是：

> 准话：有戏，但别把它当"大爆晚霞"来期待——大概率是"有颜色、有层次，不一定烧透"的中档晚霞。
> 最佳时间：17:10—17:35。找西边视野开阔的地方。不用带伞。

**交互（DeepSeek 同款）**：🌐 亮起 = 每条回答都先联网搜一次；熄灭 = 纯本地学问；
消息里粘链接自动读正文；含 6 位数字自动带行情；"/搜 问题" 强制搜一次。

**浏览器语音的现实**（重要）：Web Speech API 的后端是**浏览器厂商的云**——
Chrome=谷歌（国内被墙，必挂）、Edge=微软（国内大概率可用）、Safari=苹果。
网页无法直接调 OS 级识别器；桌面端的零代码替代是 **Win+H**（Windows 11 系统语音输入，
任意浏览器输入框直接打字）。失败提示已按此分支指引。
